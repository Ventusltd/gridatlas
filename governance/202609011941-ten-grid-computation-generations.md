# Ten grid-computation generations

Each generation changes a computation contract, owner data product, or proof.
None is a cosmetic version. Promotion remains one generation at a time.

1. **202609011941 — click computation envelope.** Coordinate declared PoC,
   mapped measurements and voltage-scoped NESO facts. Explicit missing lanes;
   no fetch/render/inference. Module and adversarial proof included here.
2. **Owner-product pin.** Publish `map-click-network.v1` from data-grid-gb main
   with SHA-256, source hashes, counts and reconciliation; consumer verifies all
   four before indexing and fails closed on drift.
3. **Audited project-to-site identity.** Move REPD→ETYS site-code and voltage
   bindings into a cited data-grid-gb product. No normalised-name fallback may
   reach electrical computation.
4. **Voltage-specific fault duty.** Select only the declared connection voltage
   and exact named Appendix D metric/scenario; prove no cross-voltage envelope
   and no RMS-break/peak/DC conflation.
5. **One-hop topology.** Present existing circuits, transformers, neighbouring
   sites and explicit unknown terminal voltages from Appendix B, with R/X/B
   carried on their published 100 MVA basis and no impedance arithmetic.
6. **Planned topology delta.** Separate existing network from each ETYS future
   year; classify add/remove/change without implying delivery, availability or
   project causation. Preserve unresolved planned-change appearances.
7. **Two-hop customer-substation chain.** For cited schemes only, compute
   project→customer substation→transmission site as separate measured legs;
   encode built/not-built/under-construction state independently of OSM.
8. **Distribution archetypes.** Model circuit-loop and DNO PoCs such as Little
   Crow without inventing a transmission node; add DNO/ENA source contract and
   keep transmission topology explicitly not applicable.
9. **Click-anywhere regional census.** Combine mapped geometry and published
   located points into distance bands while disclosing unmatched/unlocated
   owner records and quarantining `distinctive_tokens` joins.
10. **Validated solver boundary.** Export a solver-neutral bus/branch case with
    declared assumptions, taps, scenarios and provenance. Do not calculate
    headroom until compared against a trusted load-flow solver and golden cases;
    UI remains facts-only until that acceptance gate passes.

Every generation requires: module proof, real-owner-product contract proof,
composition gate, historical computation scan, mobile PipelineNews→GridAtlas
journey, immutable timestamp, and board receipt.
