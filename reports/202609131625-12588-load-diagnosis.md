## Controlled dependency isolation

Every control/experimental context used identical route interception, disabling cache effects equally. Matching requests were held for 20 seconds, then continued to the real server. Application code and response bytes were not replaced. Holding a request is a causal experiment, not a claim that the public service was down.

| Case | Substation geometry ready | Five links available | State at 8 seconds |
|---|---:|---:|---|
| Passthrough control | 1.789 s | 1.971 s | Five links rendered |
| Hold connection-register request | 0.811 s | 20.914 s | 5,800 substations loaded; zero links; no arrival result; no specific waiting status |
| Hold DuckDB module request | 0.923 s | 0.923 s | Five links rendered; identity verification pending |
| Hold substation-geometry requests | 20.544 s | 20.839 s | Zero substations and zero links |

In the held connection-register case, the independent REPD identity owner had resolved Botley West at 3.559 seconds. The grid links nevertheless remained absent until the held request returned. At 28 seconds, all five links were present and rendered. No uncaught JavaScript errors occurred in any of the four controlled cases.

## Confirmed control-flow defect

File: atlas/cartridges/202609080850-sld-sandbox-v9-8.js

Lines 6068–6101: selectAt awaits loadSubstations(), clears the loading status, computes other context, then awaits resolveNesoConnection() BEFORE calling drawLinks(). This is applied to the onshore Botley arrival as well as the other eligible arrivals.

Lines 1897–1920: loadNesoSites() caches a promise around an XMLHttpRequest to atlas/data/neso-connection-sites.lean.json. There is no xhr.timeout, ontimeout or onabort handling. A request that remains pending leaves that promise pending. The catch outside an await does not impose a timeout.

Result: an additional connection-register lookup gates the already-available nearest-substation drawing. Because the preceding loading status is cleared before this await, the waiting stage is not clearly explained on screen. The 20-second hold reproduces the reported class of symptom: project shown, no grid links, followed much later by all five links.

The request is not needed for the geometric nearest-neighbour calculation itself. Delaying DuckDB by the same amount did not hold those lines back. This rules out the identity runtime as a necessary blocking dependency for this coordinate-complete URL in the tested path, not as a source of all possible page-performance issues.

A separate required dependency also has an unbounded application wait: loadSubstations() at lines 3471–3503 awaits fetch() and response.json() without an application-level deadline/abort. Delaying that geometry likewise delays the lines, as expected.

## Certainty boundary

These tests establish two reproducible loading paths and one unnecessary serial dependency. They do not establish which request stalled in the original phone session: its network trace was not captured. Nor do they prove all iOS-specific scheduling, memory-pressure, WebGL or background-tab issues absent. The original report is not dismissed because the clean runner was fast.

## Minimal repair specification — not applied

1. For onshore nearest-mapped results, draw once required geometry is ready; resolve declared connection enrichment independently. Clearly distinguish nearest mapped assets from declared connections, and pending/unavailable metadata from confirmed absence. Preserve offshore declared-connection semantics.
2. Add bounded, retryable network handling to geometry and register loaders. A timer should yield a visible pending/unavailable state, not fabricate geometry or declare a project unconnectable. Avoid retaining failed promises indefinitely.
3. Protect every asynchronous enrichment with the current selection epoch, including after the connection-register await, so a late result cannot overwrite a different selected project.
4. Keep a specific loading stage visible until each requested result is delivered or explicitly unavailable. Do not let the identity label imply the grid is waiting for identity when it is waiting for connection metadata.
5. Retain this exact URL as a canary. Acceptance must include cold/warm runs, delayed register, delayed geometry, delayed identity, failure/retry and rapid reselection. Confirm first rendered links as well as telemetry. Add physical-iPhone validation before claiming iOS coverage.

No UI, branding, homepage, release, production pointer, calculation or dataset was changed. Only two diagnostic scripts, two push-only diagnostic workflows and this report were added on test/12588-load-diagnosis-202609131625. No deployment, recurring monitoring or production fix was performed.
