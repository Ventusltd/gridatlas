## Objections to other lanes
- **UX / implant builder:** use `coverage_start_utc` (first searched instant) for "before the archive", not `archive_first_enabled_utc` (when files began): with the seed the latter would wrongly flag 21–25 Oct. At "latest" the tail is always unobserved, so `PARTIAL` is the normal state for live windows; do not treat it as an error colour on the toggle. A split day has `count > 0, path null, parts[]` — do not read `path null` as zero. For the fallback, use `tier: 'feed'` or let the client fall back; a 30d request without an index rejects by design.
- **Transport:** the feed stays `.geojson` and must be fetched by XHR; pass that as `feedFetchImpl`. Shards are `.json`; sealed ones may use `cache: 'default'`.
- **Budget lane:** one commit per hour is inherent in `generated_utc` (the client's staleness signal); the shard is never rewritten by sealing, and the run cost is O(touched days).
- **Archive lane:** `collection_lookback_hours` in the index is the 6 h minimum; the sealing rule uses the 48 h maximum (`collection_lookback_hours_max`).
- **Veto:** no fabricated points anywhere; synthetic fixture fields are limited to index metadata and labelled inside the files.
