## Method and commands
- Inventory: every file in `tools/proofs` (81 catalogue entries incl. 17 module proofs, 16 superseded-generation proofs, 3 python/PowerShell steps, 3 live-site runs); what each tests, kind, target, dependencies and invocation are in `run-baseline.mjs` (`catalogue()`) and `baseline-table.md`.
- Serving: `python3 -m http.server 8107 --directory /home/claude` → `http://127.0.0.1:8107/gridatlas/atlas/` (log `server-8107.log`).
- Probe: `probe-route.mjs` (Chromium 1440x1000 and 393x852; wait = map+60 proxies ≤40 s, network idle ≤20 s, fixed 3 s) → `probe/`.
- Table 1 (as-is): `node run-baseline.mjs --group static|historical|python|browser|live --out baseline-<group>` with per-proof SIGKILL timeouts (process group). Outputs `baseline-*/results.{json,md}`, logs per proof under `baseline-*/logs/<id>/{stdout,stderr}.log`.
- Table 2 (shim): `node run-baseline.mjs --group browser --shim --out baseline-browser-shim` — `shim-preload.cjs` (`NODE_OPTIONS=--require`) patches `chromium.launch` so every context an UNMODIFIED proof creates gets `installOfflineShim()` plus a pass-through for `raw.githubusercontent.com/Ventusltd/<not lightning>` (reachable here); per-context served/aborted/missing lists in `logs/<id>/shim.jsonl`.
- Assessment: `node assess.mjs --dirs … --out baseline-table.md` merges the groups and adds an *assessed* column (machine result kept verbatim; overrides listed in the file with reasons).
- Comparison harness: `compare-candidate.mjs` (identical contexts, DOM/geometry/style/network manifests, masked pure-Node PNG diff); self-parity runs `self-parity/` (no shim) and `self-parity-shim/`; V5 as a candidate: `compare-v5-preview/`.
- Lightning cases: `lightning-cases.mjs --adapter adapters/v5-preview.mjs` → `lightning-cases-v5/`; candidate template `adapters/candidate.template.mjs`.
- CI record: `gh api repos/Ventusltd/gridatlas/actions/...` (read-only).
- Protocol for the candidate: `CANDIDATE-PROTOCOL.md` (identical-conditions table, behaviour-by-proof matrix, lightning cases, acceptance rule); every script above takes the candidate URL/label and diffs against these baselines (`assess.mjs --diff baseline-table.json`).

## Objections to other lanes
- Visual lane: the regression is the Layers-panel reflow, not the black map. Compare `label.key-item`/`.key-group` rects and the Grid panel's first child, and do not accept "first group" placement because the preview's proof asks for it.
- Transport lane: `.json` passing `legacyStem()` is necessary, but the candidate's lightning path must never enter `queryOnDemand()` (DuckDB); the archive must stay `.json` shards (PR #1), which the harness answers from `--lightning-data-dir`.
- Builder lane: anything prepended to `#scada-ui-container` or `#fs-curtain-keys` moves every original control (finding 5); the engine's `buildDOM()` also wipes both containers (`202609062358-substation-intelligence-v9-63.js:1070-1072`), so a control added before boot is destroyed and one added after must survive a rebuild — the compare harness's `layers-panel` and `fullscreen` scenes catch both.
- Lead/harness: the highest-value fix is a `+esm` stand-in (duckdb-browser.mjs imports only `apache-arrow`; serve `+esm` as that file with the bare import rewritten to a cached arrow ESM build): it unblocks 48 layer clicks, 13 technology buckets, Pipeline News, solar CSV and the REPD arrivals.

## Recommendation for the smallest additive integration
Add nothing to the original's DOM order. Lightning should be one `label.key-item` appended as the LAST row of the LAST existing group in `#scada-ui-container` and `#fs-curtain-keys` (or a new last group after the Basemap group), with the same classes as its siblings, no `data-layer-id`/`data-pn-layer`, re-appended after any `buildDOM()`; its menu proxy appended last in the Grid panel; the style layer added only on first switch-on (not at boot), so `compare-candidate.mjs` reads 0 geometry deltas, equal map layer lists and 0 masked pixels with lightning OFF. Its label must carry count, latest-detection time, "satellite optical, not ground strikes", a reason on failure and a stale flag; the archive client must expose per-date scanned/unknown. Accept only when `candidate-table.md` diffed against `baseline-table.md`/`baseline-shim-table.md` shows no PASS→other change and `lightning-cases` has no FAIL.
