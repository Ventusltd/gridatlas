## Method and commands

1. Server: `python3 -m http.server 8102 --directory /home/claude &`.
2. Harness (reusable, task 4): `E/parity-harness.mjs` (sha256 `0317604252c4…`), Playwright imported from `/home/claude/gridatlas/node_modules/playwright/index.mjs`. 4. Runs (all outputs under `E/runs/`):

6. Masking policy: `#clock, #date, #days`; the trailing `[…]` live status/count suffix of every layer label (measured with a DOM `Range`, so only the suffix glyphs are masked); the map canvas (shim style is background-only, no tiles) with every UI overlay rect carved back out so dropdowns, cards, sheets, curtain and controls over the map are still compared; and the declared additive Weather region in BOTH images. Nothing else.
7. Threshold: a pixel is "changed" when any channel differs by >16/255; PASS needs ≤0.1 % changed of the unmasked area AND every surface rect within 1 CSS px AND identical computed styles/counts/inventories. Justification: self-check measures exactly 0.000 % and 0 geometry diffs in all 24 cells, so the floor is zero; 0.1 % of 1440x900 (1,296 px) is below one relabelled 10-px word (~2,400 px) and far below one inserted 44-px phone row (~17,000 px, ≈5 %). Any non-zero result is therefore a real difference.

3. Menu-contract lane: the preview's Grid toggle carries `data-gridatlas-layer-proxy="weather:uk_lightning"`, making the proxy census 64 while `inspect()` still says 63. A proof keyed on `>= 60` passes; one keyed on `=== 63` fails. State which one is the contract.

5. Fullscreen lanes: see F5 — test both the Fullscreen-API path and the CSS-only path; they paint different surfaces.
6. Harness lanes: results captured without the shim (or with WebKit claimed) are BLOCKED_HARNESS, not evidence.

## Recommendation for the smallest additive integration (visual-parity terms)

- Keep lightning OFF by default; never PREPEND. In `#scada-ui-container` and `#fs-curtain-keys` (2-column grids) APPEND the Weather group as the 14th `.key-group`: it lands in the empty cell beside REPD (row 7, column 2) and the 13 original cells keep their exact rects (REPD is taller than one row), so with lightning OFF the panel is geometry-identical and on phones the group is below the fold.
- Do not add anything inside the Grid dropdown's `.gm-panel-body` on desktop: it is `column-count` balanced and the panel is height-capped (`max-height:min(72dvh,620px)`), so any insertion, even last, moves original rows (F3). Either accept and declare the Grid dropdown as the additive region (append LAST, after REPD, which is displacement-free below 560 px) or put the toggle at the end of a panel that is not height-constrained (View has 5 items), keeping six menus.
- Reuse the original `[WAIT]/[OK]/[FAIL]` suffix convention and inline `style.color` so the live-count mask and styles match the originals.
- Acceptance gate for the candidate lane: `cd E && node parity-harness.mjs --baseline http://127.0.0.1:<port>/gridatlas/atlas/ --candidate <candidate url> --out ./runs/candidate --additive '<candidate's additive selector(s)>' [--lightning-data-dir <synthetic shards>]` must exit 0 (PASS) on all 24 cells; the additive selector may mask the control, but no original surface may move.

## Verdict

**FAIL** — the rejected preview displaces every original layer surface (14th group prepended to 2-column grids and a balanced multi-column dropdown; 400kV moves 31→740 px x on desktop, +56/+71 px y on phones; 35–40 geometry diffs and 1.1–4.3 % pixel change in every visible state with lightning OFF), while the shell chrome, styles and z-order are untouched; local browser evidence is only valid under the offline shim because the allowlist blocks the MapLibre engine itself (F1).
