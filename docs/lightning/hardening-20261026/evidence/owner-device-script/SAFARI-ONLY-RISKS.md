# Safari/iPhone-only risks: lightning 202610270024

This lane is documentation only: no browser and no WebKit. Every risk below comes from reading the source, and none has been measured on WebKit. Each status is therefore **UNVERIFIED (BLOCKED_HARNESS: no iOS WebKit)** until the owner's phone check (OWNER-PHONE-CHECK.md) or a WebKit run settles it.

Sources:
- Module: `wt/atlas/modules/202610270024-uk-lightning-overlay.js`, where `L` means a line number.
- Shell: `wt/atlas/releases/202608300453-atlas-v9/{ventusv8.css,ventus-corev8engine.js,index.html}`.
- Dash toggle: `wt/atlas/cartridges/202610270024-sld-sandbox-v9-8.js`, around L2515–2600.

| # | Risk | Why it is iPhone/Safari-specific | Source | Caught by owner step |
|---|---|---|---|---|
| S1 | **There is no real fullscreen on iPhone, so HIDE LAYERS stays on screen in "fullscreen".** | The dash toggle hides itself only when `document.fullscreenElement` or `document.webkitFullscreenElement` is set. iPhone Safari has no element Fullscreen API, so the shell falls back to CSS pseudo-fullscreen (`body.fs-active`). The fixed z-index 9999 button stays visible over the `#fs-curtain` (z 505, max-height 70dvh). Chromium/Android lanes hid it, so their fullscreen M01 results do not transfer. | cartridge `reflectFullscreen`; engine L393–409 | 8 |
| S2 | **The `fit()` padding is computed once and only on resize or orientation change.** | On a phone, the module installs while the panel is collapsed. The curtain twin is `display:none` until `fs-active`, so its rect is 0, which gives `paddingRight` 0 and `paddingBottom` = innerHeight − button top + 16. iOS also changes `innerHeight` when the toolbar shows or hides. Opening fullscreen fires no resize, so the curtain twin keeps install-time padding. If the curtain ever reaches the button region, text could sit under it. With max-height 70dvh it should not on an 844 px screen, but this is not measured. | L174, L181 | 7, 8 (portrait and landscape) |
| S3 | **The lightning group may become narrow on a phone.** | `paddingRight` = group.right − button.left + 16 is applied to the **whole** group. If the panel spans the full phone width, this takes away about 130–150 px (the width of "▾ HIDE LAYERS"). The caption, about 25–35 lines at 12 px, must then scroll inside `.scada-wrapper` at `max-height:28vh` (about 236 px at ≤480 px width). The text stays readable but needs long scrolling. Not measured on WebKit. | L174; css `@media (max-width:480px)` | 7 |
| S4 | **Page pinch-zoom breaks the padding sums.** | iOS ignores `user-scalable=no` for pinch-zoom. When the page is pinch-zoomed, `innerHeight` reports the visual viewport but `getBoundingClientRect` uses the layout viewport, so `fit()` can over- or under-pad. | L174; shell viewport meta | 7 if the owner pinch-zooms the page instead of the map |
| S5 | **The feed may be served from the XHR HTTP cache.** | The live feed uses XMLHttpRequest with no cache directive. raw.githubusercontent.com sends a max-age of about 300 s, so Safari may show a feed up to about 5 minutes old after "LATEST", or after switching off and on. The STALE rule (4 h) hides nothing. The visible effect is only a Refresh time a few minutes behind GitHub. | L28–30 | 4 (Refresh time) |
| S6 | **Timers are throttled.** | Background tabs, Low Power Mode and in-app browsers suspend `setInterval`, so the 10-minute auto-refresh (L171) does not run while the page is hidden. Nothing refreshes immediately on return. The caption can be hours old until the next tick or a chip tap. STALE appears after 4 h, which is honest, but the counts look frozen. | L171 | none (note only) |
| S7 | **The back-forward cache restores the page while ON.** | Safari's bfcache restores a page with JavaScript state intact. After navigating away and pressing Back, lightning can still be ON. This does not break "never persisted", because a reload is still OFF, but a tester may report it as persistence. | L169–172 | 9 (reload, not Back) |
| S8 | **The native date picker.** | iOS shows a wheel picker for `input[type=date]`. When there is no archive index, `min` is not set (L155). iOS does not enforce `min`/`max` in the picker. Future dates are allowed and clamped by `min(to+1 day, now)`. An empty value (Clear) fails the date pattern (DRE) and shows "Custom dates: From must not be after To — nothing loaded". That wording is wrong for an empty field, but nothing loads, which is correct. The 11 px input font would trigger iOS focus-zoom, but the shell's `maximum-scale=1.0` suppresses it. | L132, L155, L161–162 | 6a |
| S9 | **The dots are tiny on Retina.** | The circle radius interpolates from 2.2 px at zoom 4 to 4 px at zoom 8. At the starting zoom of 4.2, a dot is about 2.3 CSS px, which is hard to see on a dark basemap. The owner's "48H: none obvious" (M03) is consistent with this. It is not a data loss. | L128 | 6b |
| S10 | **The outside-view count is not live.** | `r.out` is counted only when the caption is built, on load or chip tap. The moveend recount was cut for byte budget. On a touch device the user pans constantly, so the line can say "in view" for dots that were panned away. This applies to every browser but is most noticeable on a phone. | L101; E-progress "moveend recount dropped" | 6c (re-tap needed) |
| S11 | **In-app browsers differ from Safari.** | SFSafariViewController and WKWebView inside ChatGPT, LinkedIn or Mail have different toolbar heights and safe-area insets, and may lack `dvh` on older iOS. The 26 Oct veto screenshots came from an in-app browser. | — | Before you start (repeat step 7 in the in-app browser) |
| S12 | **Coarse-pointer detection decides the mode.** | `matchMedia('(pointer: coarse)')` is true on iPhone, which selects phone mode (10,000-point cap, 44 px buttons) and the caption word "phone". An iPad with a keyboard or trackpad, or Safari's "Request Desktop Website", may report fine-pointer and width >700, which selects desktop mode (40,000 cap, wording "for this desktop"). This is correct behaviour, but strings differ from the sheet. | L20, L141 | 5 (cap wording) |
| S13 | **VoiceOver chatter.** | The caption is `role="status" aria-live="polite"` and has 7 long lines. Every chip tap makes VoiceOver read the whole block. That is an accessibility nuisance, not a failure. | L139 | not covered |
