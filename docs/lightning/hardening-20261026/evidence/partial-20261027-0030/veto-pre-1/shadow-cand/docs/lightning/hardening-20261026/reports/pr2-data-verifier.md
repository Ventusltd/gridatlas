## 4. Defect list (for the owner's separate decision; nothing pushed)

Severity scale from the brief: release-blocker / defect / cosmetic. None is a release-blocker for the GridAtlas overlay, whose failure handling is explicit; D-1 and D-4 touch the archive's honesty and the heartbeat promise directly.

**D-1 — False zero after a lost shard (defect).** `history.py:382` iterates `set(disk) | set(incoming_by_day)` only, so a day whose shard file is missing (but listed in the index) is never visited; `history.py:470-476` then writes `count 0` for it because scan windows cover the date. Repro: `python3 EV/exp4_defect_hypotheses.py EV/wt EV/exp4-defects` §H1 → `run 1: coverage full, count 2` then `run 2: coverage full, count 0, path None`. Expected: `ValueError: … listed in the index but missing on disk` (the check already exists at `history.py:279-280` but is reached only when `listed == present`, `:394`). Proposed minimal fix (validated in `EV/scratch-fix/`, 49/49 tests pass, retention test re-run): add `indexed = {d for d, r in old_rows.items() if d >= cutoff.isoformat() and (r.get("path") or r.get("parts"))}` and iterate `sorted(set(disk) | set(incoming_by_day) | indexed)`; call `_verify_unchanged(archive_dir, old_row)` before the `listed == present` comparison. Patch: `EV/proposed-fix-h1-h3.patch`.

**D-2 — Burst above ~46 k flashes/hour freezes the archive for up to 7 days (defect; OWNER_DECISION on mitigation).** `history.py:259-262` raises `ShardTooLarge` for one hourly part > 25 MB; the raise aborts the whole ingest after earlier days were written and before the index is written (`:421` vs `:528`). Because the run record carries the whole 7-day feed (`collect.py:397`), every hourly run re-raises until the burst hour leaves the feed; the index is not rewritten in that period, so those runs' scan windows and *all* their incoming flashes (any day) never reach the archive; afterwards the burst day is `coverage none / count null` (honest, but lost) — repro §H2. Options: (a) isolate per day — catch `ShardTooLarge` inside the day loop, keep that day's previous row/files, report `failed_days` in the result and status, still write the index (rows must keep `count>0 ⇒ path|parts`, which both consumers enforce); (b) split below hourly (10-minute slot parts) when an hourly part exceeds the cap — needs a new part path pattern in both consumers; (c) raise `MAX_SHARD_BYTES` (GitHub warns at 50 MiB). Recommend (a) now, (b) later.

**D-3 — `slots_parsed:false` ignored → whole query window (incl. unpublished tail) archived as searched (defect, low likelihood).** `collect.py:319-320` returns the full window when no product name parses; `history.py:557-562` records it as a successful window regardless of `record["slots_parsed"]`. Repro §H3: `scanned_seconds 21600` for a 6 h window with two opaque product names. Expected: coverage unknown (or flagged). Fix (validated, in the same patch): in `windows_from_run_record` return `[]` when `record.get("slots_parsed") is False`, and surface the flag in `status.json`.

**D-4 — Heartbeat not committed while `data/history` does not exist (defect).** `.github/workflows/update-lightning.yml:102` `git add -A data/history data/status.json` → `fatal: pathspec 'data/history' did not match any files`, exit 128, nothing staged (git 2.43 probe, section recorded in this report; same behaviour on ubuntu-latest git). PR #2 ships no `data/history/` directory, so every failed run before the first successful archive write (missing secrets, EUMETSAT outage) ends with an uncommitted status.json and a red step 5, contradicting "status always writes heartbeat"; the next run's `read_last_success` then finds neither status nor index. Fix: `git add -A data/status.json; if [ -d data/history ]; then git add -A data/history; fi` (or commit an empty `data/history/.gitkeep`).

**D-5 — Masked-value guard can never fire (cosmetic, pre-existing on main collect.py:91).** `collect.py:122` tests `getattr(x, "mask", False) is True`; a numpy `MaskedConstant.mask` is `array(True)`, never the `True` singleton. Safe by accident: masked coordinates become NaN and fail `inside_uk_view`; masked times fail `parse_utc`. Fix: `numpy.ma.is_masked(x)`.

**D-6 — Dropped-record visibility (cosmetic).** The feed path drops out-of-box/malformed records without counting them (`collect.py:81-82,120-131,195-206`); the archive counts `dropped_invalid` but `status.py:113-121` does not copy it into `status.json` (§H7). Fix: count rejects in `decode_body` into the run record; add `dropped_invalid` to `status.archive`.

**D-7 — "archive not yet published" prefix on schema-mismatch (cosmetic).** `history-window.mjs:318` and overlay line 102 (`NA`) prefix the index error with "not yet published" even when the index exists but is unsupported/corrupt. Fix: "archive unavailable:".

**D-8 — Seed windows frozen at 21c3e567 (remark, OWNER_DECISION).** `data/seed_scan_windows.json` omits every main run after 13:05 UTC 26 Oct (the live feed is already at 38f2126, 17:30–20:30, 17 products). Under-claim only; regenerate the seed from the feed history at merge time, and decide whether the "one slot short = unpublished tail" reconstruction rule is acceptable or whether seed days should carry only flash-proven slots (`slots_proved_by_flashes`).
