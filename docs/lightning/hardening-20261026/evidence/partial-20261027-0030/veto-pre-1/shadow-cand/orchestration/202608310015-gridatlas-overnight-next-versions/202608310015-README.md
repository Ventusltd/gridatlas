# 202608310015 GridAtlas overnight next-versions programme

This programme watches `Ventusltd/gridatlas` from generation `202608310015`, studies the current repository and every new timestamped artifact produced on `main` or a newly updated branch, then emits additive candidate folders for browser testing.

## Hard boundaries

- The first candidate cannot be built until at least 3,600 seconds of recorded study have elapsed.
- Every observation and every candidate has a new timestamped folder.
- `atlas/current.json`, the repository root route, existing releases, and the frozen `202608300453-atlas-v9` shell are never modified by the controller.
- A candidate is a thin loader plus a candidate-local composition. It is not a copied application.
- New cartridges are composed only when a timestamped `gridatlas.composition-manifest.v1` or `gridatlas.current.v2` artifact passes SHA-256, shell-slot, and required-cartridge validation.
- No candidate is promoted. Browser failures are committed as quarantine evidence rather than hidden.
- `Ventusltd/cvaa` is read-only provenance and is never written by this programme.

## Output routes

Study evidence is written under:

`nightly/202608310015-gridatlas-overnight-next-versions/runs/<timestamp>-gridatlas-study-artifact-.../`

Mature candidates are written under:

`nightly/<timestamp>-gridatlas-app-candidate-.../`

The conventional `index.html` and `current.json` names exist only inside each timestamped candidate folder so GitHub Pages can serve the app directly.

## Timer

The workflow starts on installation, rescans every 15 minutes during the overnight window, and records the actual study start and `not_before` time in the programme ledger. New source fingerprints after the one-hour gate produce new candidate versions without reusing an earlier folder.
