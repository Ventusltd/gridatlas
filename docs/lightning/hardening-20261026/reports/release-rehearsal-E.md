## Pre-existing failures on main, and what the release must do about each
1. **Lint and `loop.mjs state` fail** with "active workflow budget mismatch": the tenth workflow is `uk-lightning-preview.yml`, and `loop.mjs` allows nine.
   - AGENTS.md requires `loop.mjs state` in the pointer commit, so the release cannot be made correctly without fixing this.
   - **The release must be preceded by a separate commit that deletes that workflow** (commit 2, `ac35bc6`/`747eee0`). Merge with rebase-and-merge, or merge it as its own PR first.
   - Do not fold the deletion into the release commit. Otherwise `git revert` of the release would bring the workflow back and break lint, and the revert would no longer be a clean, byte-exact rollback.
2. **Data-contract parity fails three original rows:**
   - `sld-sandbox: declared source derived/gb-transmission-network.v1.json is named by the bytes`;
   - `sld-sandbox: … derived/price-decade-rollup.json …`;
   - `substation-intelligence: … derived/connection-points.v3.json …`.

   The original 202609241334 and 202609062358 bytes name these products in a form that the proof's `PRODUCT_URL` matcher does not see.
   - **The release commit must do nothing about them.** Fixing them would mean editing original cartridges, manifests or the proof, which the invariants forbid in a pointer release.
   - It must not introduce new FAILs, and it doesn't: after release, parity is exactly these three FAILs, plus six new PASS rows for lightning `data/history/` and `data/uk_lightning.geojson`.
   - The OWNER_DECISION is to track them separately.
