## 2. Behaviour contract of the module

- **Install gate**: polls every 250 ms and watches the document (MutationObserver) until `__GRIDATLAS_MODULES__.menuBar.installed === true`, `__GRIDATLAS_PIPELINE_LAYERS__.installed`, a map handle (`__GRIDATLAS_V9_MAP__`), the populated `#scada-ui-container` and the Grid panel body exist; never gives up silently (`state.waiting_for` names what is missing). Not gated on `map.isStyleLoaded()`.
- **Surfaces, appended never prepended**: one `.key-group` (title "Weather · EUMETSAT Lightning Imager") appended LAST to `#scada-ui-container` and to `#fs-curtain-keys` with the same `appendChild` Pipeline News uses; a toggle-only `.gm-layer` row in a new flex child inserted directly after `.gm-panel-body` of the Grid panel (before `#fs-curtain-tab`). The 13 original groups keep their order (Topology first); `menuBar.inspect()` stays `{60,3,63,63,true}`; `[data-gridatlas-layer-proxy]` and `[data-gridatlas-layer-key]` stay 63.
- **Attributes the toggle does NOT carry**: `data-layer-id`, `data-pn-layer`, `data-gridatlas-layer-proxy`, `data-gridatlas-layer-key`, `lbl-*` ids, `name="bm"`. The menu's document click listener (substation-intelligence 6065–6076) is bubble-phase, so the Grid row stops the click at itself and the panel stays open exactly as it does for the 63 proxies; ArrowDown still lands on `engine:400`.
- **OFF by default, never persisted**: no request, no source, no layer and no main-thread work beyond building the hidden control until the first switch-on; no localStorage/sessionStorage/cookie; a reload is OFF. Switching OFF removes the source and layer, so the style's layer list returns to the OFF snapshot (100 layers in the harness).
- **Transport**: `fetch(absoluteUrl, {cache, signal})` of `.json` resources only (`data/history/index.json` and `days/YYYY/MM/DD.json`, `cache:'no-cache'` for the index and unsealed days, `'default'` for sealed days), AbortController 15 s, 4 shards in flight, `allSettled` semantics with per-day failures named, LRU of 8 shards. The live 7-day feed `uk_lightning.geojson` is read by `XMLHttpRequest` (the original bridge hooks only `window.fetch`); it is the only `.geojson` literal in the module. The bridge's counters stay at delta 0 (`intercepted_on_demand` 0, `failures` 0 after ON).
- **Index v2 semantics** (PLAN §7): `count null` = never searched = unknown; `count 0` only with scanned time; a split day has `count > 0, path null, parts[]` and only the parts overlapping the window are fetched; "latest" windows are normally PARTIAL (tail not yet ingested) — a warning, not an error; `coverage_start_utc` (not `archive_first_enabled_utc`) marks "before the archive"; stale when `now − generated_utc > 4 h` or `now > next_update_due_utc`.
- **Tiers**: 12h/24h/48h/7d/30d/custom ≤ 31 days → day files when the index sum is ≤ 40,000 flashes and ≤ 32 MB, else overview (index counts) with a LOAD POINTS consent that downloads the newest days until 40,000 and says "N downloaded from the newest k of n days"; 3m/6m/12m/custom > 31 days → index-only daily counts, map layer emptied. Windows are UTC, end-anchored, `[start,end)`; PREV/NEXT/LATEST move named periods; PREV is disabled below the retention cutoff and the start is clamped and labelled; custom = inclusive UTC dates with APPLY (From > To is refused with a red border and a caption message).
- **Caps (coordinator's binding addendum)**: raw points up to 10,000 on a coarse pointer or ≤ 700 px viewport and 40,000 on a desktop, decided from the index count of the files about to be fetched BEFORE any download (from the feed count on the fallback path); above the cap the GeoJSON source is created with `cluster:true, clusterRadius 40, clusterMaxZoom 10` and the single circle layer sizes clusters by a `step` on `point_count` (no symbol or text layer). The flashes caption line records which cap applied and why, e.g. "408 drawn as points (index count 408 within the 10,000-point cap for this phone)" or "310 drawn as clusters (index count 119,902 exceeds the 40,000-point cap for this desktop)". `setData` with a fresh FeatureCollection per load; no `updateData`.
- **Fallback while the archive is unpublished** (index 404 or unparsable): the live feed is loaded by XHR, features filtered client-side to the window, 30D/3M/6M/12M chips disabled, and the caption says "Refresh live feed … (last collection window … ; latest detection … ; 7-day retention; archive not yet published: <reason>; earlier hours unknown, not zero)". A window older than 7 days fails visibly with "needs the archive (archive not yet published)".
- **States and colours**: LOADING #888 → READY·DETAIL / READY·SUMMARY / EMPTY-COVERED #00ff88, PARTIAL #ffcc00, UNKNOWN / BEFORE-ARCHIVE #ff8800, FAIL #ff4444, STALE as a modifier. ## 4. Deviations from the plan and the UX specification, with reasons

1. **Index v1 is not accepted** (PLAN 3.2 asked for v1 and v2). The byte budget forced the choice: v2 is the only shape the data plane will publish (lightning branch `data-plane/hourly-lookback-index-v2`; its `history.py` upgrades v1 on ingest). A v1 index is refused visibly: "Archive unavailable: unsupported index schema uk-lightning-history-index.v1 … (unknown, not zero)".
2. **No overview drill-down chips** (UX control set). CUSTOM with a single date gives the same detail view.
3. **PREV/NEXT/LATEST move named periods only**; for CUSTOM the date inputs are the navigation (the buttons are disabled).
4. **FAIL keeps the toggle ON** with the red state, the reason and whatever loaded (e.g. 219 of 408 with the missing day named), so the reason stays readable and LATEST/period retry is possible; the veto's V10 wording "the toggle returns to OFF on error" was not followed because the UX state machine (binding per PLAN 3.5) defines FAIL as a displayed state. Switching OFF clears everything.
5. **Grid-footer reachability on desktop**: `#map-container` is `overflow:hidden` and 520 px tall at 1440×900, while the Grid panel is 620 px tall; the panel's bottom 140 px — including the ORIGINAL's own "⬇ Layers" tab — is unreachable without programmatic scrolling at 1440×900 and 1280×720 (pre-existing; `verify/15-grid-clip-probe.txt`). The footer row therefore sits in that clipped band on those two desktop sizes; it is hittable at 1920×1080 and on phones (360×740, 393×852), where the panel is `position:fixed`. On desktop the Layers panel is open by default and carries the primary control. If the lead prefers, the mirror can move into `.gm-panel-head` as a `role="checkbox"` div (not matched by the ArrowDown focus query, ignored by the click closer) in a three-line change; it was left in the PLAN-specified slot.
6. The composition manifest's current-shaped identity keys were set to this generation (see §1, row 4).
